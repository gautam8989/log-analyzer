Two structured parsers, plus a fallback for everything else

SSH auth logs and web access logs get full structured analysis. Anything else — firewall logs, application logs, systemd journals, custom formats — still gets scanned line-by-line for the patterns below, just without the format-specific context (no "which field is the username" type reasoning).

Brute force auth
One IP racking up repeated failed logins against SSH.
Failed password for root from 192.168.1.5 ×7
Post-failure success auth
A run of failed logins immediately followed by a success — likely a cracked password.
7 failed → Accepted password for root from 192.168.1.5
Username enumeration auth
One source probing many non-existent accounts.
Invalid user admin, test, oracle, postgres, ubuntu...
SQL injection access + generic
Query strings — or any line — carrying classic SQLi payloads.
/index.php?id=1' OR '1'='1
Cross-site scripting access + generic
Script tags or event-handler payloads, anywhere in the line.
/search?q=<script>alert(1)</script>
Path traversal access + generic
Attempts to climb out of a web root or file tree.
GET /../../etc/passwd
Automated scanning access
A burst of 404/403 responses to one IP, or a known scanner user-agent.
11 × 404 from one IP UA: sqlmap/1.7
Attack tool mentions generic
Any line referencing sqlmap, nikto, hydra, metasploit, and similar tools.
blocked request from hydra scan attempt
Repeated failure language generic
Lines with "access denied", "unauthorized", "auth failure", etc., clustered by IP if one is present.
10.0.0.4: permission denied ×6
High-volume source generic
One IP responsible for an outsized share of all lines with an address in them.
203.0.113.5: 40% of all IP-bearing lines

How a log line becomes a finding

The same three-stage pipeline as the Python CLI it's built on, reimplemented in JavaScript so it runs without a server.

Parse

Each line is matched against a format-specific pattern and turned into a structured event — timestamp, source IP, user or path, status.

Detect

Independent rule functions scan the parsed events for known attack signatures and score each hit by severity.

Report

Findings are sorted high to low severity with supporting evidence, ready to hand to an incident writeup.
